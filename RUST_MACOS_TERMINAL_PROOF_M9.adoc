= LeanBun Rust macOS Terminal Proof M9
:toc: left
:sectnums:

== 结论

M9 使用 exact `rustix =1.1.4` safe API 补齐 effective-user ownership、foreground process group 与 controlling-terminal
session proof。调用仍位于独立 `leanbun-approval-macos`，不读取 response、不生成 grant、不写 replay state，也不调用 Lake。

== Dependency boundary

Cargo 关闭 default features，只开启 `std`、`process`、`termios`。本地上游源码固定在隔离开发库，Git commit、annotated tag
object、crates.io checksum、relevant source hashes 和许可证均进入
xref:doc/rustix-v1.1.4/SOURCES.adoc[rustix 来源记录]。

tag 没有签名，因此不声称签名 provenance。Cargo registry source 与 Git checkout 的 relevant API 文件逐字相同。

== Proof conjunction

公开 observer 先完成 M8 terminal identity，再通过 safe rustix API 观察：

* effective UID 与 terminal owner UID；
* current process group 与 terminal foreground process group；
* current process session 与 controlling-terminal session；
* syscall observation 后再次取得 stdin/stderr device identity，拒绝漂移。

owner、foreground 或 session 不一致分别产生 typed denial；查询失败或 device 漂移产生
`DeniedUnverifiableTerminal`。全部一致只产生 `ReadyForChallengeResponse`，execution authority 仍为 `Withheld`。

== Live verification

非 TTY 运行实际得到 `DeniedNonInteractive`。同一 observer 在隔离 PTY 中实际观察到 stdin/stderr 同设备、UID 相等、PGID 相等、
SID 相等，得到 `ReadyForChallengeResponse`；没有读取任何输入，authority 仍 withheld。

Rust tests 另覆盖 owner、foreground、session mismatch 的拒绝优先级。Bun boundary oracle 确认 exact rustix version、五个 safe API、
无 input reader、无 environment authority、无 process spawn、无 LeanBun unsafe block。
