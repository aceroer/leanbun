= LeanBun M5 Read-Only Reuse Candidate Check
:toc: left
:sectnums:

== 状态

M5 第十四阶段新增只读入口：

[source,shell]
----
leanbun build reuse-check <project> <target>
----

它只报告 `eligible` 或 `miss`，`buildExecution` 永远是 `not-attempted`。当前没有 reused 执行状态，
不运行 Lake、不创建 execution record，也不获取或删除 build lock。

== 候选协议

. 完成与受控构建相同的 provider inspection、binding/image authorization 和全部 dependency artifact 重验；
. 在不存在同 project/image active build lock 时只读扫描 execution store，最多接受 10000 条严格记录；
. 只选择 `completed`、Lake exit 0、进程组已收割、所有后验 stable 且带 reuse evidence 的记录；
. 精确匹配 project ID/path、image、target、binding SHA 与 attestation SHA；
. 按 `finishedAt` 选择最新兼容候选，execution ID 作为确定性 tie-break；
. 实时重算 project input 与整个 `.lake/build`，比较 schema、SHA-256、entry/file/byte count 和 missing roots；
. 哈希完成后再次检查 build lock，避免把与活动构建重叠的观察报告为 eligible。

这是一个时间点快照。未来若实际跳过 Lake，仍必须先获取 project/image lock，并在锁内重新验证，不能直接
消费本报告。

== 拒绝语义

* 没有完整兼容记录：`REUSE_CANDIDATE_NOT_FOUND`；
* 项目输入不一致：`REUSE_INPUT_MISMATCH`；
* 项目输出不一致或缺失：`REUSE_OUTPUT_MISMATCH`；
* 检查前后出现 active writer：`BUILD_LOCK_BUSY`；
* 全部匹配：`REUSE_CANDIDATE_ELIGIBLE`。

损坏或非 canonical execution record 会令整个扫描 fail closed，不能被静默跳过。
