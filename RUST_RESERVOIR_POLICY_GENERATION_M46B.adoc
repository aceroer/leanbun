== Completion status

M46 Phase B pure policy and generation authority are complete as `0.17.0-m46b-dev`. The outcome precedence and rebind scope were recorded before implementation in
xref:RESERVOIR_RESOLUTION_REBIND_POLICY_M46B.adoc[LeanBun Reservoir Resolution and Rebind Policy M46 Phase B].

This phase consumes M46A's immutable companion. It still performs no public registry query, persistent publication or external-project mutation. Phase C will place the same models behind repository-owned loopback and durable fixture state.

== Typed resolution outcomes

`evaluate_reservoir_binding_v1` now distinguishes:

* `FirstResolutionPending`;
* `StableBinding`;
* `AmbiguousCandidates`;
* `MetadataDrift`;
* `VersionRebound`;
* `DisappearedBinding`;
* `ContentMismatch`;
* `ExplicitRebindAccepted`.

The evaluator is pure and bounded. Registry/package/requested-version scope mismatch is rejected rather than mislabeled as ordinary drift. A first observation can only become pending. A same-version commit change remains `VersionRebound` unless an exact rebind claim is supplied.

== Explicit rebind claim

`ReservoirRebindAuthorizationV1` identity-binds the registry, package, requested version, old/new commits, newly observed metadata, active binding identity and proposed binding identity. It requires a changed commit.

The evaluator rejects stale metadata, changed proposal identity, wrong active identity, stable-binding use, ambiguous observations and first-binding use. `ExplicitRebindAccepted` is still a pure decision result, not a persistent user approval token; Phase C/later mutation entry must bind it to an independently authorized transaction.

== Generation authority

`LeanBunGenerationV1::new` remains the compatibility constructor for graphs without Reservoir requests. `new_with_reservoir_bindings` adds an explicit companion input.

Generation validation now uses the M33 request kind and enforces:

* no companion on a non-Reservoir graph;
* mandatory companion for any Reservoir graph;
* an explicit requested version for every Reservoir package;
* exact equality of companion and graph package sets;
* version, resolved URL, exact commit, download integrity, source tree and selected-source equality across graph/lock/companion.

Non-Reservoir generation uses the unchanged `leanbun-generation-v1` metadata and V1 identity domain. Reservoir generation uses `leanbun-generation-v2`, records `reservoir-bindings-sha256`, and includes that identity under a V2 generation identity domain. This makes adjacency insufficient: a different companion necessarily produces a different generation.
