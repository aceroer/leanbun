:toc: left

== Result

M44 Phase A is complete as `0.13.0-m44a-dev`. The current-generation lock, exact-source and package-path decision model has been mechanically extracted from the mixed `leanbun-package` namespace into `leanbun-lock`.

No lock field, parser rule, ordering rule, error precedence, digest domain, path decision or resolver behavior changed. Inventory/drift remains in `leanbun-package` for Phase B, and Reservoir and `StrictJson` semantics remain outside this milestone.

== Physical boundary

`leanbun-lock` contains the unchanged M31 `lock_v1.rs`, a narrow crate root and the moved M31 golden example. Its only workspace dependency is `leanbun-core`.

The six mainline roots now declare and import `leanbun-lock` directly:

* `leanbun-lake-bridge`;
* `leanbun-resolver`;
* `leanbun-store`;
* `leanbun-generation`;
* `leanbun-build`;
* `leanbun-managed`.

Their complete Cargo closures contain no `leanbun-package`, `leanbun-plan`, `leanbun-state`, `leanbun-approval-macos` or `leanbun-macos-acl-sys` edge. Source scanning also finds no `leanbun_package`, `PackageInventoryV1`, `DependencyDrift*`, `build_package_inventory` or `report_dependency_drift` reference under those six roots.

`leanbun-package` temporarily re-exports the lock API solely for historical consumers and compatibility. Mainline use of that bridge is rejected by the dependency checker. Phase B must remove this compatibility edge while extracting `leanbun-inventory-legacy`.

== Enforced dependency gate

The architecture checker now selects the M44A 14-crate graph when `leanbun-lock` exists. It requires:

* `leanbun-lock` depends exactly and only on `leanbun-core`;
* each mainline root has a direct `leanbun-lock` dependency;
* no mainline transitive closure reaches the mixed package or historical policy crates;
* the moved lock source still matches its M43 digest;
* every M31/M42 protected file not intentionally changed by the crate-root compatibility re-export remains byte-identical.

The one intentionally changed protected source is the old mixed `leanbun-package/src/lib.rs`: its local `lock_v1` module declaration became a compatibility re-export from `leanbun-lock`. This exception is explicit and confined to Phase A; the lock implementation itself is still verified byte-for-byte at its new path.
