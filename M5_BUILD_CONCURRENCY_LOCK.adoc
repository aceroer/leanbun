= LeanBun M5 Project/Image Build Concurrency Lock
:toc: left
:sectnums:

== 状态

M5 第十二阶段已经在受控构建事务外层加入 project/image 级排他锁。同一个 canonical project ID 与
sealed image ID 在任一时刻只能有一个 active execution；target 不进入锁 key，因此同一绑定下的不同
target 也不能并行写共享项目构建目录。

== 锁协议

. 对 canonical `{projectId,imageId}` 编码计算 SHA-256 key；
. 在 state root 的 `build-locks/<key>.lock` 以 `O_EXCL|O_NOFOLLOW` 创建；
. 写入 execution ID、项目、镜像、target、协调 PID 与获取时间，`fsync` 后改为 `0444` 并立即严格回读；
. 已存在锁只做有界只读发布等待，随后返回 `BUILD_LOCK_BUSY`；损坏、逃逸或所有权冲突均 fail closed；
. 锁在 execution record 之前获取，覆盖 Lake 执行、cwd 审计和全部后验重验；
. terminal record 原子发布后，按 execution/project/image 精确所有权释放并同步目录；
. 进程组未确认收割时，record 与锁都保持 active，交给显式 recovery。

锁不按年龄过期，也不允许另一执行接管。崩溃若发生在 terminal record 发布与释放之间，`build recover`
只有在协调 PID 已消失、项目 cwd 无活动进程且锁与 record 全字段一致时，才补做释放；`running` record
则还必须完成原有全证据审计并先终结为 `failed`。

== 测试

临时目录测试覆盖只读 mode、严格所有权释放、symlink store 拒绝，以及两个独立 Bun 进程同时争抢。
跨进程测试确认恰有一个 `acquired`、一个 `busy`；发布窗口的短暂不可读只允许有界等待，不能触发删除。
另有 terminal-record/release 崩溃窗口测试，确认显式恢复不改写既有终态，只释放匹配锁。
