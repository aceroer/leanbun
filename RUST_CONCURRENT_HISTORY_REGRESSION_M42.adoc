:toc: left

== Result

M42 Phase E 已在 `0.11.0-m42-dev` 闭合 M42 最后一段路线：

[source,shell]
----
leanbun fixture-regress <registered-fixture-repository> \
  --fixture=concurrent-history
----

该入口不接受项目路径。单次运行创建三个 barrier-synchronized worker：两个执行完整 `negative-matrix`，第三个读取
登记 malformed manifest 并要求实际 parser 返回 `JSON_MALFORMED`。它不并行写同一个 managed project，也不开放外部项目。

== Concurrent publication correction

Phase D 的 `negative-latest` 使用 atomic rename，但发布者随后错误要求 latest 仍指向自己的 record。两个合法 worker 并发时，
另一个完整 pointer 可以在检查前获胜，旧判断会误报失败。

Phase E 将 post-publish invariant 修正为：当前 latest 必须是 `0600` bounded regular file、schema canonical、fixture 固定，且其
run ID 与 record SHA-256 必须绑定 `negative-records` 中某个 `0400` immutable record。发布者不再要求自己永久获胜。
run ID 仍由时间、进程和 process-atomic nonce 唯一化；两轮中四个 worker records 均不同。

== Terminal records

每个 worker 都获得 scheduler-bound job ID，并在 `regression/terminal-records` 发布一个 `0400` terminal record：

* 两个负矩阵 worker 为 `terminal=passed`，绑定各自 outcome record SHA-256；
* malformed worker 为 `terminal=failed`、`failure-code=JSON_MALFORMED`，没有伪造成功 outcome record；
* worker 非预期失败时仍先写 failed terminal，然后整个聚合入口失败。

这使“预期失败”成为可审计 terminal，而不是只依赖进程 stderr 或退出码。

== History audit and retention

审计器逐项验证四类历史：positive、negative、terminal 与 prior audit。每个 record 必须是 `0400` bounded regular file，
首尾 schema、identity 字段、文件名和内容 SHA-256 相符；positive/negative latest 必须是 `0600` 并精确绑定 immutable record。
排序后的 namespace/name/digest 形成 inventory SHA-256。

审计摘要发布到 `regression/audit-records/<run-id>.record`，独立 `audit-latest.record` 以 atomic rename 更新。
保留策略冻结为：

----
retention-policy=retain-all-v1
automatic-deletion=disabled
----

Phase E 没有删除 API、时间阈值或数量阈值。第二轮只允许新增四个 negative records、六个 terminal records 中的后三个，
以及一个 audit record；第一轮所有证据必须仍存在。

未 notarize 的 macOS arm64 development artifact。
