== Result

M42 Phase B 已在 `0.8.0-m42-dev` 将本库 `lake-managed-dependency` 接入可重复回归：

[source,shell]
----
leanbun fixture-regress "$LEANBUN_REPOSITORY" \
  --fixture=lake-managed-dependency
----

命令不接受项目路径。每次都从登记模板创建独立副本，执行 dry-run、adopt、baseline build、
`--package=managed_dep` 等价的显式 update、updated build、`BeforeActiveRename` fault、recover、rollback 和 final build。

== Per-run state boundary

运行项目位于：

----
.leanbun-dev-rust/managed-fixture/m42-regression/runs/<run-id>/project
----

dry-run 生成唯一 project ID 后，cleanup guard 只登记以下五类 exact target：

* 本次 run root；
* `.leanbun-dev-rust/managed-projects/registry/<project-id>.record`；
* `.leanbun-dev-rust/managed-projects/generation-state/projects/<project-id>`；
* `.leanbun-dev-rust/managed-projects/project-control/<project-id>`；
* `.leanbun-dev-rust/store-fixture/m40-managed/<project-id>`。

加入 cleanup set 前要求四个 project-ID state target 均不存在，避免误删既有状态。清理拒绝 symlink/special file，
递归恢复权限后只删除 exact target 并同步父目录。M41 project ID `9aaa5805...` 从不进入该集合。

== Closure invariants

每次成功同时证明：

* baseline generation 与 rollback generation 相同，updated generation 不同；
* baseline、updated、rollback 三次 build artifact 相同；
* fault 后 active 仍是 updated，pending evidence 存在；
* recover 清除 pending，rollback 回到 adopted transaction；
* template tree 与项目源码未变，`vendor/managed_dep/.lake` 不存在；
* recovery 后无 `.active-*.tmp`；
* 摘要发布前五类 project-scoped 状态全部清理。

== Parallel probe correction

全量并行测试暴露旧 `probe_declaration` staging 只使用系统时间；两个同进程 probe 可能得到相同值，一个失败 guard
会删除另一个正在使用的目录。staging identity 现加入进程内 `AtomicU64` nonce，单测重跑与全工作区并行回归均通过。
