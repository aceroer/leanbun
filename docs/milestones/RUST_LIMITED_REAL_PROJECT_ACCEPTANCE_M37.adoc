= Rejected GRSC External-Project Experiment
:toc: left
:sectnums:

== Status correction

本记录不再被认定为 M37 或真实项目验收。执行时错误地只观察了 GRSC 子仓库的 `lean/` 目录，没有先读取完整 GRSC 项目群和子仓库根文件树；该目录只是 source-attribution interface，不是一个适合作为小型测试库的独立项目边界。

事务已经回滚，GRSC 没有进入 managed mode。下文只保留已发生运行的技术证据，不赋予 milestone、production support 或 adoption 资格。强制测试项目边界见
xref:../../TEST_PROJECT_BOUNDARY.adoc[LeanBun Test Project Boundary]。

本次项目边界为：

----
$M37_REJECTED_EXTERNAL_PROJECT/lean
----

目标固定为 `GRSC`，工具链固定为 `leanprover/lean4:v4.32.0`，依赖闭包固定为 Bun development package set 中的 Mathlib 九包。事务没有网络来源，也没有执行 `lake update`、clone、checkout、clean 或 toolchain 变更。

== Adoption boundary

项目原有 `.lake/package-overrides.json` 指向生产 dependency library。该旁路实验没有覆盖它，而是通过 exact Lake invocation 的 `--packages=<Bun runtime projection>` 注入九个 Bun 最终决策路径。这使一次构建可以验证 Bun 的路径权威，同时默认项目入口始终保留旧路径，回滚不依赖重写项目配置。

事务只允许写入：

* 项目 `.leanbun/m37` 的私有控制记录；
* Lake 自身受控的 `.lake/build` 与 `.lake/config`；
* `/dev/null`、标准输入输出描述符。

Seatbelt 拒绝网络和其他文件写入。项目源文件、`lakefile.lean`、`lean-toolchain`、`lake-manifest.json`、旧 package override 和九包 dependency image 均被事务前后摘要绑定。

== Transaction and recovery

入口首先核对项目配置、toolchain、manifest、旧 override、exact Lake binary、Bun runtime projection 与已有 source attestation 的固定 SHA-256。控制目录只允许两个起点：不存在，或首次前置取证留下的完全空目录；任何已有记录都会拒绝歧义重跑。

首次取证发现 Mathlib 的既有 `.lake/build/bin/cache` 为 95 MiB，超过 immutable source store 的 64 MiB 单文件门。该次执行在 Lake 启动前 fail closed，只留下空目录。修正没有放宽 source/download 门：构建制品改用独立流式摘要，限制为单文件 1 GiB、整树 16 GiB、五十万条目，并拒绝 symlink 与特殊文件。

正式事务顺序为：

. 写入 retained override、baseline record 和 baseline active record；
. 对故意不存在的 target 运行同一 supervisor，得到 `lake-nonzero`，并证明 active 未改变；
. 以 Bun 九包 runtime projection 两次运行真实 `lake build GRSC`；
. 验证两次项目制品摘要一致，项目 protected input 与完整 dependency image 前后相同；
. 写入 immutable candidate record，原子发布 candidate active 并立即稳定回读；
. 原子恢复 baseline active，稳定回读后写入最终 acceptance record。

旧 generation、candidate 与失败证据均保留，没有自动删除或按时间猜测恢复。
