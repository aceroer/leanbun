== Completion status

M45 is complete as `0.15.0-m45-dev`. The placement audit was recorded before movement in
xref:../decisions/STRICT_JSON_PLACEMENT_DECISION_M45.adoc[LeanBun Strict JSON Placement Decision M45]. Its selected boundary has now been implemented and validated.

This is a mechanical ownership change. It does not add Reservoir authority, change lock bytes, resolve packages, publish caches or authorize an external project mutation.

== Implemented boundary

`leanbun-codec` is a new platform-neutral crate depending only on `leanbun-core`. It owns:

* `StrictJson` and `JsonNumber`;
* the bounded strict parser and its depth/node limits;
* `StrictJsonError`, preserving `JSON_MALFORMED` and the prior byte-positioned message.

`leanbun-evidence` depends directly on codec and retains:

* stable bounded file reads and SHA-256;
* canonical path containment and Unix file identity checks;
* `StableJsonFile` and `read_strict_json`;
* conversion from `StrictJsonError` to `EvidenceError`.

Evidence temporarily re-exports the pure symbols for source compatibility. Direct parser consumers in `leanbun-lake-bridge`, `leanbun-managed` and `leanbun-plan` now import `leanbun-codec` explicitly.

== Decoder compatibility gate

The pure parser retained the full grammar, lexical number preservation, duplicate-key rejection, trailing-content rejection, Unicode surrogate validation, and deterministic depth/node limits.

The Lake root-probe regression now names all five M45 boundary cases and requires every one to retain `LakeBridgeErrorKind::MalformedProbeOutput`:

* malformed JSON;
* unknown fields;
* duplicate keys;
* trailing content;
* oversized bounded fields.

Stable evidence oversized-file behavior remains independently covered by the evidence reader tests. Moving the parser therefore did not merge byte acquisition policy with in-memory syntax policy.

== Remaining boundary

M46 must separately choose a versioned Reservoir binding format and compatibility route. M45 neither assumes JSON nor silently extends `LeanBunLockV1`. If M46 chooses strict JSON for a pure binding document, it may depend directly on codec without acquiring evidence filesystem policy.
