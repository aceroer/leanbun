= LeanBun M5 Sandboxed Lake Build Probe
:toc: left
:sectnums:

== 状态

M5 第七阶段已在 `.leanbun-dev` 内实际执行一个无依赖 Lake target。该入口是 sandbox 能力探针，不是正式
项目构建授权：它强制 dependency-free manifest、匹配 toolchain、开发根 containment 和至少一个模拟
protected root。

[source,shell]
----
leanbun build lake-probe <dev-project> <target> <dev-protected-root>
----

== 同进程协议

. 规范化项目、隔离 Elan/Lake 和 protected root，全部必须位于 `.leanbun-dev`；
. 要求 `lake-manifest.json` 的 packages 为空且 `lean-toolchain` 匹配；
. 准备只允许 `.lake/build` 与 `.leanbun/tmp` 写入的 Seatbelt profile；
. 对项目和 protected root 做完整 metadata/content 快照；
. 以参数数组运行固定 Lake proxy：`lake --verbose build <target>`；
. 构建后再次完整快照，要求 protected root tree hash 相同、项目非允许写区记录逐字节相同；
. 对生成的 `.lake/build` 计算 canonical artifact tree hash。

Elan 的 `bin/lake` 是依赖 `argv[0]` 分派工具的代理链接。LeanBun 会验证 link target 仍位于隔离
`ELAN_HOME`，但执行时保留原始 `bin/lake` 路径；直接执行 realpath 后的 `elan` 会把 `build` 错当成 Elan
参数，本阶段已用一次受控失败验证该 API 边界。
