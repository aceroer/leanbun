= LeanBun M5 Lock-Held Reuse Transaction
:toc: left
:sectnums:

== 状态

M5 第十五阶段开放隔离开发项目的显式复用入口：

[source,shell]
----
leanbun build reuse <project> <target>
----

该入口可以在完整验证后跳过 Lake，但不自动替代 `controlled-probe`，也不对真实项目开放。调用方必须显式
选择 reuse；失败不会静默回退为正常构建。

== 事务顺序

. 只读载入 canonical project binding 与 sealed attestation，确定 project/image lock key；
. 排他获取 project/image build lock；
. 记录项目 protected snapshot，立即发布 `running` execution record；
. 在锁内完成 provider inspection、112425 个 dependency artifact 全量重验、binding/attestation 稳定性复核；
. 只从实际 Lake `completed` 记录中选择同 project/image/target 与相同 binding/attestation SHA 的最新候选；
. 实时重算 project input 与 `.lake/build` 输出全部 SHA-256 和计数；
. 再次确认项目 protected records 未变；
. 全部通过时原子终结为 `reused`，随后按所有权释放锁；
. 任一条件失败则原子终结为 `failed`、`failureStage=reuse-verification`，释放锁并要求调用方显式运行正常构建。

`reused` record 使用 `reusePolicySha256`，不伪装成 Seatbelt `profileSha256`；它没有 Lake exit、termination
reason 或 process group 字段，并通过 `reusedFromExecutionId` 指向实际 Lake source record。候选选择不接受
`reused` 作为来源，因此不会形成无限复用链。

锁后快照失败会在 record 创建前释放锁。record 终态化已经开始后若发生 store/release 异常，不会尝试第二次
终结；遗留 terminal/running lock 继续由既有显式 recovery 审计处理。
