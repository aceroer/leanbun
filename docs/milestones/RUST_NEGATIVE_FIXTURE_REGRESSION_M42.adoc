== Result

M42 Phase D 已在 `0.10.0-m42-dev` 将五类登记负输入接入独立矩阵：

[source,shell]
----
leanbun fixture-regress "$LEANBUN_REPOSITORY" \
  --fixture=negative-matrix
----

命令不接受项目路径，不创建 execution copy，也不进入通用外部项目。输入只来自
`test/fixtures/m42-negative`，其完整 tree SHA-256 固定为
`99be7b47137350fa7d1fc274f54fd15eedbfca3637e31964a92be7ba2991690d`。

== Rejection matrix

[cols="2,2,4",options="header"]
|===
|Case |Required rejection |Boundary

|`malformed-manifest`
|`JSON_MALFORMED`
|严格 JSON/project manifest parser

|`path-escape`
|`PATH_ESCAPES_ALLOWED_ROOT`
|project input lexical containment，在 lookup 前拒绝 `../outside`

|`hash-drift`
|`TREE_DIGEST_MISMATCH`
|M34 immutable Store 对实际 local-directory tree 与候选 expected tree 的比较

|`cycle`
|`DEPENDENCY_CYCLE`
|M33 resolver 对登记 TSV 中 `a -> b -> a` 的图验证

|`missing-package`
|`REGISTERED_CLOSURE_INCOMPLETE`
|M40 registered provider closure 要求 project manifest 精确等于九包集合
|===

hash-drift 不是 revision 字符串差异的替代测试。它建立进程唯一 Store scratch，调用真实
`LeanImmutableStoreV1::fetch_and_publish`，要求 `TreeDigestMismatch`，随后只删除该 exact scratch；两轮后 scratch 根均为空。

== Evidence separation

正向成功证据仍位于 `regression/records` 与 `regression/latest.record`。负矩阵在每次执行前后都快照并比较：

* 每个正向 record 的文件名、SHA-256 与 Unix mode；
* 正向 latest 的完整 bytes 与 Unix mode；
* 负输入 tree identity。

五项拒绝全部正确且上述快照不变后，聚合器才将 `0400` immutable record 写入
`regression/negative-records`，并以 atomic rename 更新独立的 `0600` `negative-latest.record`。负证据发布后再次比较正向快照。
