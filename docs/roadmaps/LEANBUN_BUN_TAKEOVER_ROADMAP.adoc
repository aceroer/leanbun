== Roadmap status

本路线承接 xref:../architecture/BUN_LEAN_PACKAGE_TAKEOVER_M30.adoc[M30 Bun-Managed Lean Package Takeover]，是 M31 起的唯一主线。

当前状态：*M38 仓库内工程发布已完成*，验收见
xref:../milestones/RUST_BUN_RELEASE_INTEGRATION_M38.adoc[LeanBun-enabled Bun Release Integration M38]。锁定 Bun fork 的单一 Rust binary 已完成 source compatibility、显式 loopback update、M37 replay、版本化安装、升级、恢复与 rollback；当前为 ad-hoc signed、未 notarize、unborn 主仓库的 fixture development release，公开签名发行仍关闭。M37 使用本库 `lake-basic` fixture 完成，验收见
xref:../milestones/RUST_REPOSITORY_FIXTURE_ACCEPTANCE_M37.adoc[LeanBun Repository-Local Fixture Acceptance M37]。此前 GRSC 运行因项目边界选择错误已降级为
xref:../milestones/RUST_LIMITED_REAL_PROJECT_ACCEPTANCE_M37.adoc[rejected external-project experiment]，不参与 M37。下一门为 M38 release-binary integration；所有测试与 replay 继续遵循
xref:../../TEST_PROJECT_BOUNDARY.adoc[LeanBun Test Project Boundary]。

目标分为两个完成点：

* *工程完成（M37）*：本仓库登记的最小 Lean fixture 可由 Bun 完成依赖解析、锁定、路径决议、隔离编译、验证、失败恢复和原子发布；
* *发布完成（M38）*：Lean package adapter 编入锁定的 Rust Bun fork，形成带来源、版本、签名和回滚证据的单二进制交付。

M27--M29 的 privileged/XPC 路线保留为旁支研究，不进入关键路径。M38 之后的跨平台、分布式 cache、live path development、自动 GC 和任意
post-update hook 支持均是可选扩展，不属于 v1 完成条件。

== Permanent invariants

所有后续 milestone 必须同时保持：

. Bun 是 resolved graph、package bytes、final path、transaction 和 publication 的最终决策者；
. Lake 只接收 Bun 生成的完整 runtime packages projection，并保留 config/target/build semantics；
. Lean 保留 compiler/elaborator/kernel；
. managed workflow 永不调用 `lake update`，也不允许 Lake 隐式 clone、checkout、clean 或改变 toolchain；
. manifest、workspace override、runtime override 不再并列决策；每个 package 必须恰有一个 `PackagePathDecisionV1`；
. 同一 provenance 内重复 package、未知 package、缺失 package、path escape、tree drift 和实际 workspace path mismatch 全部 fail closed；
. `leanbun.lock` 不含机器绝对 store path；active generation 才绑定 location-specific canonical final path；
. immutable object 不原地覆盖，active generation record 是唯一 commit point；
. 所有开发测试和 M31--M38 acceptance 只使用 `test/fixtures` 的隔离副本，只写 `.leanbun-dev` / `.leanbun-dev-rust`；生产依赖库和外部项目保持只读且不得作为测试输入；
. 不引入 XPC、Authorization、LaunchDaemon、root helper、Python writer 或 shell command construction。

== M31 — Lock and final-path decision model

=== Inputs

* M30 authority/provenance rules；
* 现有 `leanbun-core` SHA/canonical identity；
* `leanbun-evidence` strict JSON、manifest、provider override 和 path containment；
* Bun `CryptoHasher` golden oracle。

=== Deliverables

* 新 Rust crate 或独立 package module，定义 `LeanBunLockV1`、`LockedLeanPackageV1`、`PackagePathProvenanceV1`、
  `PackagePathDecisionV1`；
* bounded constructor：package 数、dependency 数、字符串、URL、subdir、digest 与 graph depth 全部有限；
* `(scope bytes, name bytes)` canonical package ordering 和 dependency-edge ordering；
* `Manifest / WorkspaceOverride / RuntimeOverride` 三类 provenance，runtime 只能标为 `BunGenerated`；
* 同层 duplicate、cross-layer incompatibility、missing/extra package、ambiguous selection、absolute path in portable lock 的 typed rejection；
* canonical binary identity、strict canonical text codec、Rust/Bun shared positive/negative fixtures。

=== Exit gate

* 任意合法 lock re-encode 后逐字节相同；
* package/edge 输入顺序改变不改变 identity；任何语义字段改变必须改变 graph/decision digest；
* 不存在能构造两个 final paths 或未选择 final path 的 public state；
* Rust full suite、Bun oracle 和 malformed corpus 全通过；runtime source 不含 filesystem、network、process 或 `lake update`。

=== Stop condition

M31 不读取项目，不创建 `leanbun.lock`，不 canonicalize 真实路径，不运行 Lean/Lake。

== M32 — Lake declaration and projection bridge

=== Inputs

* M31 lock/path model；
* 锁定 Lake `Manifest.lean`、`Resolve.lean`、`Workspace.lean`、`CLI/Main.lean` source hashes；
* dependency-free 与 Mathlib 九包隔离 fixtures。

=== Deliverables

* `LakeRootDeclarationV1`：把 `lakefile.toml` 或 exact-toolchain `loadWorkspaceRoot` probe 归一成 bounded declarations；
* probe 在只读 source、禁网、独立 staging root 中运行，不调用 `loadWorkspace` 或 materialization；
* `LakeManifestProjectionV1` 和 `LakeRuntimePackagesProjectionV1` pure encoder；
* runtime projection 必须覆盖完整 locked closure、每包恰一次、按 canonical key 排序且全部为 Bun-selected path entry；
* `LakeWorkspacePathObservationV1`：读取 Lake 实际 resolved package paths，并与 `PackagePathDecisionV1` set 比较；
* exact Lake 4.32 fixture tests，覆盖三层 collision、重复 `--packages`、subdir、path/Git kind drift 和 missing manifest fallback。

=== Exit gate

* 对同一 lock，Rust projection 与 Lake `Manifest.parseEntries`/materialization input 逐字段一致；
* Mathlib fixture 的九包 final paths 全部等于 Bun decisions；
* 任意非 Bun runtime override 或 Lake 实际路径偏差返回 typed rejection；
* 只写 staging fixture；生产项目和 provider snapshot 前后摘要一致。

=== Stop condition

M32 不选择版本、不下载 package、不发布 store object、不执行 target build。

== M33 — Bun deterministic Lean resolver

=== Inputs

* M31 models、M32 declarations；
* Lake `reuseManifest`、root-priority、later-shadow 与 breadth-first dependency resolution source rules；
* 已物化的只读 local package fixtures。

=== Deliverables

* `LeanResolutionRequestV1`：root declarations、optional active lock、explicit update set、toolchain identity；
* `LeanResolutionGraphV1`：exact package closure、selected source/revision/subdir、dependency edges、conflict provenance；
* frozen mode 全量复用 active lock；update mode 只允许显式 package set 改变，其余 package exact-pin；
* Git branch/tag/Reservoir version 归一为 exact commit；path package 归一为 contained source identity；
* root declaration 优先、later require shadow earlier，但每次 shadow 必须形成显式 decision，不做 silent overwrite；
* cycle、duplicate identity、source-kind conflict、toolchain candidate conflict、missing transitive declaration 的 typed rejection；
* Lake-source-derived graph fixtures 与 property tests。

=== Exit gate

* 相同 inputs 必须产生同一 canonical graph；
* update `mathlib` 不得改变未在可证明 dependency impact closure 内的 package；
* Bun resolution 与锁定 Lake source fixtures 的选择结果一致，冲突报告比 Lake 的 last-wins 更严格；
* 无 network、无 filesystem writer、无 Lake build。

=== Stop condition

M33 只解析已给定 metadata，不获取远端内容，也不把 candidate graph 设为 active。

== M34 — Bun fetch, integrity, and immutable Lean store

=== Inputs

* M33 exact graph；
* 锁定 Bun Rust `NetworkTask`、`Integrity`、isolated store 与 Git task implementations；
* 本地 HTTP/Git mock sources，不依赖公共网络。

=== Deliverables

* Bun fork 内窄 `lean_pm` source adapter，禁止 npm peer/hoist/lifecycle semantics 泄入 Lean graph；
* `LeanFetchRequestV1`、`VerifiedDownloadBlobV1`、`VerifiedPackageObjectV1`；
* bounded concurrent fetch、task dedupe、terminal failure retention、bounded retry、取消与输出/大小限制；
* archive path traversal、absolute path、escaping symlink、special file、duplicate entry 和 decompression bomb 拒绝；
* normalized tree hash，保存 path/type/mode/size/file SHA；
* temporary slot -> verify -> file/directory sync -> digest-key atomic publication；existing object 只重验不覆盖；
* package-digest 并发争抢、crash slot、partial extraction、same-digest/different-bytes tests。

=== Exit gate

* 同一 object 的并发 fetch/extract 只有一次成功 publication；
* 注入任一 download/extract/fsync/rename failure 都不会产生可见 verified object；
* published object 可离线重验并生成 M31 path decision；
* 所有写入限定 `.leanbun-dev-rust/store-fixture`，生产 provider 不变。

=== Stop condition

M34 不发布 active project generation，不运行真实公共网络，不编译 Lean target。

== M35 — Active generation transaction and recovery

=== Inputs

* M31 lock/decision、M32 projections、M33 graph、M34 verified objects；
* 既有 M5 build lock、execution record、binding、attestation、recovery 与 fail-closed publication经验。

=== Deliverables

* `LeanBunGenerationV1`：lock SHA、graph SHA、path-decision set SHA、manifest/runtime projection SHA、toolchain、store object set；
* project-key lock、transaction ID、`Preparing -> ... -> Verified -> Published/Failed` durable record；
* immutable generation directory；active generation record 作为唯一、最后 commit point；
* 写前稳定读取、write-ahead intent、file/directory sync、原子 active publication、发布后稳定回读；
* recovery 只依据 active record 和 exact ownership：未提交 transaction 终结 failed，已提交 transaction 只补验证/释放锁；
* failpoints 覆盖每个 durable write、sync、rename、record transition 和 lock release；
* retained generation 引用图，为后续显式 GC 提供证据但 M35 不删除对象。

=== Exit gate

* 任意 crash point 后 active generation 要么保持旧值，要么完整指向新值，不存在半提交 active state；
* recovery 幂等，不按年龄猜 stale，不把未知结果标记成功；
* mixed manifest/projection 文件不能绕过 active generation hash；
* 只对临时项目和开发 state root 开放 writer。

=== Stop condition

M35 不运行 Lake build、不写真实项目、不自动删除 staging 或旧 generation。

== M36 — Supervised offline Lake build and reuse

=== Inputs

* M35 active fixture generation；
* 现有 Seatbelt sandbox、process-group timeout、execution record、artifact evidence 和 reuse transaction；
* dependency-free 与 Mathlib fixtures。

=== Deliverables

* `SupervisedLakeBuildV1`：固定 Lake executable SHA、args、cwd、environment allowlist、target allowlist、deadline/output bounds；
* staging project 获得 M35 manifest 与 Bun-only runtime packages projection；Lake 禁网且不得 update dependencies/toolchain；
* build 前比较 declarations/lock/store/path decisions，load 后比较 actual workspace paths，build 后比较 protected inputs 与 artifacts；
* `BuildImageV1` key：lock graph + path decisions + toolchain/compiler + platform + build config + target；
* 同 key 构建排他与 verified cache reuse；不同项目可共享 dependency/store/build image，但 project output 仍绑定 project-input identity；
* timeout、signal、output overflow、Lake nonzero、path drift、artifact drift、coordinator crash 的 terminal/recovery tests；
* 修正现有 path-provenance tests 将可变 volume counters 当稳定 mount identity 的并行 flake，不放宽真正的 device/mount/path checks。

=== Exit gate

* dependency-free 与 Mathlib fixture 都能从 frozen generation 离线构建；
* Lake 没有 Git/network/update 行为，九包实际路径全部由 Bun decisions 确定；
* 相同 build image 可验证复用，任意输入/输出漂移拒绝复用；
* 全量 Rust 并行与单线程、Bun、Lean integration tests 都稳定通过。

=== Stop condition

M36 仍不修改用户真实项目，不把 fixture success 宣称为 production support。

== M37 — Repository-local fixture acceptance

=== Entry approval

M37 只允许从本仓库 `test/fixtures/lake-basic` 创建隔离执行副本。模板保持只读，普通副本只位于
`.leanbun-dev/tmp` 或 `.leanbun-dev-rust/test-tmp`，generation transaction 副本只位于 `.leanbun-dev-rust/generation-fixture`；不得选择外部项目。Mathlib 补充覆盖必须使用 `mathlib-project` 副本。

=== Deliverables

* fixture adoption report：declarations、manifest、toolchain、依赖图、写入预算与预期编译；
* dry-run candidate lock/path decisions/projections，只向隔离执行副本写最小 LeanBun binding；
* 对最小空依赖闭包执行 generation publish、offline Lake build、build-image publish/reuse 与 post-build verification；M34 fetch/store 继续由本地 source fixture 单独覆盖；
* 注入一次受控失败，证明旧 active generation 和项目源码仍可用；
* 显式 rollback 到 retained generation，不删除新 generation/store evidence；
* acceptance report 记录所有源码/binary SHA、lock/generation/build-image identity、前后 project snapshot 和实际写入清单。

=== Exit gate

* 正常更新/编译、失败恢复、rollback 三条路径均通过；
* 项目源码和 `lean-toolchain` 未被静默修改，Lake 未执行 update/fetch；
* 依赖实际路径、revision、tree hash 和编译产物全部可从 active generation 反向解释；
* `lake-basic` 隔离副本可重复进入和退出 managed mode；外部项目继续保持未接管。

== M38 — LeanBun-enabled Bun release

=== Deliverables

* 在锁定 Rust Bun fork 中固化 `lean_pm` adapter 与 LeanBun CLI dispatch；
* release build 不依赖开发 TypeScript host、Python、XPC 或外部 daemon；
* binary manifest：Bun upstream commit/tree、LeanBun commit、Cargo.lock、target、build flags、binary SHA、签名/notarization 状态；
* Rust/Bun/Lake/Lean golden、M36 fixture E2E、M37 acceptance replay 全部针对 release binary 重跑；
* 安装包只新增版本化 binary/config，不迁移或删除现有 dependency store；
* rollback package 保留上一 binary、配置 schema 和 active generation reader；
* operator manual：adopt、inspect、update、build、recover、rollback、doctor、export evidence。

=== Exit gate

* fresh isolated install 和从上一开发版本升级均通过；
* unsupported Bun/Lake/Lean source hash 明确拒绝，不自动兼容；
* release binary 在无网络 frozen build、显式 network update、crash recovery 和 rollback 场景全部通过；
* 正式宣布 v1 仅支持 macOS arm64、单机、单用户和显式受管项目。

== Cross-milestone test gates

[cols="2,4",options="header"]
|===
|Gate |每门要求

|Canonicality
|Rust/Bun binary/text golden；乱序、重复、unknown、trailing、oversize 和 identity drift 反例。

|Source compatibility
|Lake/Bun exact-source SHA 仍匹配；变化必须新开兼容门，不静默刷新 golden。

|Nonmutation
|每门列出允许写根；生产 dependency library 和非目标项目做前后 snapshot。

|Crash safety
|从 M34 起对所有 publication step 注入失败；没有未验证对象或半提交 active generation。

|Path authority
|每包一个 decision；actual Lake path set 与 decision set 完全相等。

|Process safety
|从 M36 起固定 executable/args/env/cwd、禁 shell、bounded output/deadline、完整 process-group reap。

|Regression
|全量 Rust、Bun 和 Lean integration；并行 flake 必须修复，不以重复运行代替通过。
|===

== Risk register and decision points

[cols="2,3,3",options="header"]
|===
|风险 |最早决策门 |默认处理

|Bun internal crate drift/unsafe surface
|M34
|窄 adapter、固定 upstream SHA、独立审计；不把整个 npm manager 暴露给 LeanBun core。

|Executable `lakefile.lean`
|M32
|exact-toolchain read-only probe；不自写 Lean parser，不允许 probe materialize/network。

|Lake post-update hooks
|M33
|v1 默认拒绝；不因 package 需要 hook 而隐式执行。

|Live path dependency
|M31/M33
|v1 默认 immutable snapshot；live mode 延后。

|Toolchain change
|M33/M37
|独立显式 transaction，不与 package update 合并。

|Store/build image disk growth
|M34/M36
|先引用计数与报告；自动 GC 延后，M37 前提供磁盘预算。

|Lake/Bun upstream change
|所有门
|source hash mismatch fail closed，另开版本迁移 milestone。
|===

== Completion definition

M37 前不得宣称完整接管闭环已通过；M37 通过后也只能宣称“本仓库登记 fixture 的工程闭环可用”，不能据此宣称任何外部项目已接管。只有 M38 release binary、fresh install、upgrade、
recovery 和 rollback 全部在登记 fixture 上通过，才能宣称 v1 工程发布完成；外部 production adoption 始终是另行授权的操作。
