= LeanBun Managed Library Roadmap M49--M50
:toc: left
:sectnums:

== Purpose

M49 turns the existing fixture-scoped single-project controller into an
explicit, enumerable managed-library registry. M50 adds the everyday build/run
front door only after a project is registered and verified `healthy`.

The governing contract is
xref:../decisions/MANAGED_LIBRARY_INTAKE_REGISTRY_CONTRACT_M49A.adoc[Managed Library Intake and Registry Contract M49A].

== M49A — Contract freeze

Status: *complete*.

Deliverables:

* canonical local-directory input boundary;
* per-project records as the only registry truth, with no aggregate writer;
* exhaustive status vocabulary and classification precedence;
* `manage add/list/status` command and JSON-output contract;
* explicit preservation of the Lean/Lake execution boundary.

No new command or external mutation authority is delivered by M49A.

== M49B — Strict registry reader

Status: *complete*.

Deliverables:

* a bounded, stable registry enumerator in `leanbun-managed`;
* retained managed-record V1 compatibility;
* deterministic `ManagedLibraryStatusV1` classification;
* fixture-scoped `manage list` and `manage status`, including strict JSON;
* corrupt, symlink, filename mismatch, missing path, drift, pending, and mixed
  healthy/unhealthy enumeration tests.

Exit gate:

* list/status execute no Lake command, network request, repair, or write;
* one invalid entry is visible and cannot hide valid entries;
* an unsafe authority-directory failure cannot be reported as an empty list;
* all tests use repository-owned fixture copies and private development state.

Closure evidence: xref:../milestones/RUST_MANAGED_LIBRARY_REGISTRY_M49B.adoc[M49B milestone].

== M49C — Explicit fixture intake

Status: *complete*.

Deliverables:

* `manage add` parser and exact confirmation token;
* double stable snapshot around confirmation and lock acquisition;
* pending registration, generation publication, atomic activation, and reread;
* duplicate-add, retarget, moved-path, crash, and concurrent-add rejection;
* process-restart reconstruction followed by list/status verification.

Exit gate:

* only a registered copy of `test/fixtures/lake-managed-dependency` is accepted;
* intake creates no source change or project `.lake`;
* failed initial intake is recoverable and never appears `healthy`;
* successful intake appears exactly once with the expected ProjectId and
  generation.

Closure evidence: xref:../milestones/RUST_MANAGED_LIBRARY_INTAKE_M49C_M49D.adoc[M49C/D milestone].

== M49D — User-selected local-project authorization

Status: *complete*.

Deliverables:

* explicit local path authorization outside repository fixture roots;
* provider/toolchain and supported dependency preflight;
* production state-root selection and permissions review;
* migration/replay evidence for retained V1 registrations;
* operator guidance for missing, drifted, unsupported, and recovery states.

Exit gate:

* a deliberately selected small local test project passes intake, restart,
  status, update/recovery, rollback, and source-integrity checks;
* unrelated projects remain unobserved and unmanaged;
* URLs, public registry discovery, silent current-directory adoption, rebind,
  retarget, and remove remain closed unless separately authorized.

The source-tree development adapter keeps its explicit repository argument and
private repository-local authority. The production selector names
`~/Library/Application Support/LeanBun/managed-projects` and requires a real
`0700` directory; installation/runtime wiring remains a later release task.

Closure evidence: xref:../milestones/RUST_MANAGED_LIBRARY_INTAKE_M49C_M49D.adoc[M49C/D milestone].

== M50 — Managed build and run front door

Status: *complete*.

Planned commands:

[source,shell]
----
leanbun build <project-path-or-project-id>
leanbun run <project-path-or-project-id> [-- <program-arguments>...]
----

Both commands must resolve the registry entry, require `healthy`, reverify the
active generation and final paths, and only then supervise Lake. Direct `lake`
commands remain outside LeanBun and are never claimed to be intercepted.

M50 cannot begin by weakening M49 status checks or accepting an unregistered
path as a convenience fallback.

=== M50A — Stable execution selection

Status: *complete*.

The governing contract is
xref:../decisions/MANAGED_EXECUTION_FRONT_DOOR_M50A.adoc[Managed Execution Front-Door Contract M50A].
The read-only `prepare_managed_execution_v1` API resolves an exact canonical
path or ProjectId, requires strict `healthy` status, fixes the active generation
digest, and rereads by ProjectId before returning. It does not execute Lake or
write state.

=== M50B — Managed build front door

Status: *complete*.

Route the development adapter and eventual installed grammar through M50A,
reverify that the selected generation remains active, then supervise the
existing offline Lake build. Add race, non-healthy selector and ProjectId CLI
tests. The legacy fixture build syntax is not itself M50 closure.

The implementation adds a per-project advisory operation lease shared by
build, update, recover and rollback. The lease is held for the complete
selection-bound build and is released automatically if the process exits. A
competing mutation therefore fails before it can publish a pending record. Both
canonical path and ProjectId acceptance produced the same generation and
artifact for the repository-maintained small managed test project.

Closure evidence: xref:../milestones/RUST_MANAGED_BUILD_FRONT_DOOR_M50B.adoc[M50B milestone].

=== M50C — Managed run front door

Status: *complete*.

Freeze executable-target classification, exact artifact selection, `--`
argument limits, environment/cwd policy, signal and exit propagation, and the
post-build generation/artifact gate before adding a run command.

The governing contract is
xref:../decisions/MANAGED_RUN_FRONT_DOOR_M50C.adoc[Managed Run Front-Door Contract M50C].
This development front door remains within the cooperative same-user boundary
and does not reopen the archived privileged/XPC route.

The selector, build, exact executable observation, sandboxed child and post-run
reverification remain inside one per-project operation lease. Program arguments
require `--`; stdin is null, the environment is cleared and allowlisted, output
is bounded, and timeout/signal/nonzero exit results are explicit.

Closure evidence: xref:../milestones/RUST_MANAGED_RUN_FRONT_DOOR_M50C.adoc[M50C milestone].

=== M50D — Distribution and lifecycle closure

Status: *complete*.

Complete source-patch provenance, restart and rollback regression, operator
guidance, public gates and the small managed test-project acceptance sequence.

The two M50 patches replay to the exact paired Bun tree. A clean Git candidate
containing no local provider or managed state passes the public source gate,
and the initialized repository passes the deeper provider-bound suite. The
small managed project passes separate-process status, explicit update,
ProjectId build/run, rollback and canonical-path build/run while returning to
the original generation and preserving its source tree.

Closure evidence:
xref:../milestones/RUST_MANAGED_DISTRIBUTION_CLOSURE_M50D.adoc[M50D milestone].
