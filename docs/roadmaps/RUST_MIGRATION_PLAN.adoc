== 决策

IMPORTANT: Rust 迁移已按
xref:../architecture/LEANBUN_EXTERNAL_MANAGEMENT_BOUNDARY.adoc[LeanBun 外部包与依赖管理边界]修正为外部管理路线。
`leanbun-state` writer、内部 lock/recovery 和 Lake state 接管不再实施。

LeanBun 后续控制层迁移到 Rust。当前 Bun 实现冻结为行为规范、fixture 生成器与差分 oracle；在 Rust 版本完成
逐层等价验收前不删除，也不让两个实现同时写同一 state root。

第一执行门已经完成：项目已建立隔离 Cargo workspace 和零依赖 `leanbun-core`，实现 UUID/SHA/target 验证、
完整诊断词表及 Bun↔Rust 共享黄金测试；有效 CLI 尚未改变。验收见 `RUST_CORE_M0.adoc`。

项目另在 `.leanbun-dev-rust/upstream/bun` 保存一份上游 Bun `main` 的只读浅克隆，精确来源见
`config/upstream-bun.lock.json` 和 `BUN_RUST_UPSTREAM_LIBRARY.adoc`。锁定快照已有 99 个 Cargo workspace
member、1495 个 Rust 源文件且无 Zig 源文件，可用于直接研究 Rust crate/API/构建边界。

该源码库不等于当前固定的 `Bun 1.3.14+0d9b296af` 运行时：后者继续作为重构前的行为 oracle。不得用
未发布上游构建静默替换它，也不得直接依赖 Bun 内部 crate；同语言复用必须经过许可证、依赖图、unsafe/FFI
与 API 稳定性审计。

== 安全目标

* 核心 crate 使用 `#![forbid(unsafe_code)]`；确需平台 FFI 时隔离为最小 adapter crate，逐调用审计；
* 运行时不依赖 Python、Bun、Node 或动态脚本解释器；发布为固定路径、可签名、可哈希的 arm64 macOS binary；
* canonical path、state root、project root、sealed image ID 与 execution ID 使用不可混用的新类型；
* 文件发布保留 `O_EXCL`、`O_NOFOLLOW`、fsync、只读 mode、严格 schema 回读与精确所有权删除；
* 子进程参数不用 shell 拼接；环境变量使用显式 allowlist；禁止继承不受控 PATH、代理与配置目录；
* 默认拒绝 symlink escape、TOCTOU、超限记录、未知 schema、损坏 JSON 与不完整恢复证据；
* Cargo 依赖最小化并提交 `Cargo.lock`；引入 crate 前核对来源、许可证、维护状态和 transitive graph；
* release 必须记录 rustc revision、target、Cargo.lock SHA-256、源码 commit、二进制 SHA-256 与签名状态。

Rust 的所有权与类型系统降低内存安全、资源释放和并发状态错误，但不会绕过 macOS TCC。访问外置 WD 卷仍可能
首次请求“可移除宗卷”权限。迁移目标是让权限归属于稳定、可签名的 LeanBun 二进制，去掉宿主 Python
进程造成的来源混淆，并保持最小授权；不是规避系统提示。

== 分层迁移

. `leanbun-core`：identity、状态机、诊断 vocabulary、target validation；无文件和进程能力；
. `leanbun-evidence`：稳定文件读取、canonical tree hash、manifest/binding/attestation/record strict reader；
. `leanbun-package`：外部 package inventory、dependency drift 与 dry-run command plan；
. `leanbun-process`：固定 Lake/Lean 路径、参数数组、环境 allowlist、有限输出与显式调用；
. `leanbun-cli`：参数解析、JSON report 与稳定 exit code；
. 最后才迁移显式 reuse transaction 和未来统一调度。

每层先对已有 Bun fixture 运行只读 shadow comparison：JSON canonical fields、SHA-256、诊断代码、exit code 与
拒绝路径必须一致。Rust writer 只在 reader/shadow 通过后对新的隔离 state root 开放；禁止直接接管现有
`.leanbun-dev/state`。

与严格、限 schema JSON reader；仍不得实现 writer。

表面过大而被拒绝，正式实现保持零依赖，并加入流式 SHA 与严格 JSON 结构层。下一门是单一既有 schema 的
只读 typed decoder。

Provider registry typed decoder 已完成，见 `RUST_EVIDENCE_M3_PROVIDER_REGISTRY.adoc`。它只在严格、有限 JSON

Project manifest typed decoder 与 provider declaration comparison 已完成，见
