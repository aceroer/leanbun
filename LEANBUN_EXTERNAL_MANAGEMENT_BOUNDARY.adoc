== 修正决定

IMPORTANT: 本文件的“只观察/计划/调用 Lake update”路线已被
xref:BUN_LEAN_PACKAGE_TAKEOVER_M30.adoc[LeanBun Bun-Managed Lean Package Takeover M30]再次修正。当前主线由 Bun 接管 resolved lock、来源获取、
完整性、不可变 store、事务、锁、恢复和发布；Lake 保留配置/target/build semantics，Lean 保留编译/kernel。本文件其余 M0--M29 内容作为边界演进
记录保留，不再是 M30 之后的实施上位规则。

== M0--M29 历史边界

以下内容记录 M0--M29 曾采用的 passive external-manager 边界，用于解释已有 artifacts；出现冲突时一律以 M30 为准。

该阶段曾把既有文档中关于 LeanBun 自行实现 atomic seal/bind、
project/image build lock、execution recovery、cache publication 或 `leanbun-state` filesystem writer 的路线，均降为
历史安全实验。M30 已重新启用其中可验证的 transaction/lock/recovery 机制，但只用于 Bun-owned state，不冒充 Lake private cache state。

`RUST_STATE_M0.adoc` 所记录的纯函数实验可以保留作研究证据，但不接入 CLI、不继续实现 writer，也不用于解释
或改变 Lake 内部状态。

== M0--M29 历史权责分界

Lake 对以下事项保持唯一权威：

* workspace 与 package 配置加载；
* 依赖约束解析、版本选择和 manifest 生成；
* package checkout、materialization 与更新；
* `.lake` 目录、构建缓存、内部锁和增量构建状态；
* target 构建顺序、失败恢复和 cache 一致性。

LeanBun 不复制这些算法，不根据 Lake 内部文件推演可写状态，也不直接创建、替换、修复、删除或恢复上述对象。
尤其禁止：

* 写入或修补 `lake-manifest.json`、`.lake/package-overrides.json` 和 `.lake` 内部记录；
* 模拟 Lake dependency resolver、build scheduler、cache key 或内部 lock lifecycle；
* 绕过 Lake CLI 直接切换 package checkout、恢复构件或清理 cache；
* 根据 PID、文件年龄或残留锁自动判定并恢复 Lake 事务；
* 将 LeanBun 自己的 execution/image/lock 状态解释为 Lake 的真实状态。

== M0--M29 历史外部管理面

LeanBun 只提供四类能力：

. *观察*：只读发现 Lean、Lake、Mathlib、项目配置、manifest、package checkout、revision、dirty 状态及已有构件；
. *计划*：把用户意图转换为可审阅的 Lake 命令、cwd、环境、预期写入范围和风险说明；
. *调用*：得到显式许可后，以固定可执行路径和参数数组调用公开、版本锁定的 Lake/Lean/Elan CLI；
. *核验*：比较调用前后的外部证据，报告 Lake 实际产生的 manifest、checkout、构建结果和漂移，不自行修复。

LeanBun 可以维护自己的配置、审计日志和“防止 LeanBun 重复启动同一外部命令”的任务级互斥；这些对象必须位于
LeanBun 自有目录，不能放入 `.lake`，不能替代 Lake lock，也不能用于接管或恢复 Lake 操作。

== M0--M29 历史包管理工作流

包操作统一遵循以下外部流程：

. 读取当前外部证据并形成 inventory；
. 生成 dry-run command plan，明确将调用的 Lake 命令及可能写入；
. 向用户展示版本、revision、网络、checkout 与构建影响；
. 只有显式授权后才执行 Lake CLI；
. 重新读取 manifest、package checkout 和命令退出状态；
. 报告“Lake 实际完成了什么”，不把 LeanBun 的推测当作解析结果。

例如，更新依赖时由 Lake 自己执行受支持的 update 命令。LeanBun 可以在调用前后备份或比较用户明确指定的外部
文件，但不得自行编辑 manifest 或移动 `.lake/packages` 来伪造更新结果。

== M0--M29 历史 API 边界

Rust/Bun 侧稳定 API 应围绕外部管理对象组织：

* `PackageInventory`：从公开文件和 checkout 观察得到的事实；
* `DependencyDriftReport`：声明、manifest 与实际 checkout 的只读差异；
* `LakeCommandPlan`：绝对 executable、参数、cwd、环境 allowlist、权限和预期影响；
* `LakeCommandResult`：exit code、有限输出及调用后重新观察的事实；
* `AuditRecord`：LeanBun 自己的操作记录，不是 Lake state。

禁止建立以可写 Lake 内部状态为职责的 `leanbun-state`、resolver、cache writer 或 recovery API。
