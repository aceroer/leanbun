== 结论

M4 通过。LeanBun 在一个真实、已登记的 Lean 4.32 下游项目上完成 filesystem-only inspect；检查前后
完整目录快照一致，没有创建、删除或修改项目文件，没有执行 Lake workspace 命令，也没有网络权限。

== 执行约束

验收使用 `config/leanbun-inspect.sb`：

* `(deny network*)`；
* 默认拒绝文件写入，只允许 LeanBun 仓库和标准设备端点；
* `(deny process-exec (regex #"/lake$"))`，并已单独验证 Lake 启动会被拒绝；
* provider 显式指向生产 dependency library，但只有读取权限；
* Bun 固定为 `1.3.14+0d9b296af`，入口使用 `--no-install --no-env-file`。

完整快照由 `scripts/nonmutation-snapshot.ts` 生成，覆盖根目录、子目录、普通文件和 symlink 的类型、mode、
uid/gid、size、mtime/ctime、inode/device、link count；普通文件另从受保护文件描述符计算 SHA-256。

== 共享库交叉验证

在同一个 sandbox 中运行既有只读接口：

[source,text]
----
project=.../grsc-zeta-modern-arithmetic/lean
toolchain=leanprover/lean4:v4.32.0
mathlib_rev=81a5d257c8e410db227a6665ed08f64fea08e997
dependency_count=9
verified: .../lean -> lean4-v4.32.0_mathlib-81a5d257c8e4
----

其结果与 LeanBun 报告一致。系统 `/usr/bin/python3` 会尝试建立 Xcode `xcrun_db` 并被 sandbox 拒绝；
最终干净证据改用 `/opt/homebrew/bin/python3`，且设置 `PYTHONDONTWRITEBYTECODE=1`。
