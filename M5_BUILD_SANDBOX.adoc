== 状态

M5 第六阶段已实现 build sandbox profile、参数数组 runner 与隔离写入探针。当前仍不调用 Lake；探针 CLI
只允许项目与模拟 protected root 位于 `.leanbun-dev`，避免用生产依赖测试一个尚未验证的 deny 规则：

[source,shell]
----
leanbun build sandbox-probe <dev-project> <dev-protected-root>
----

== Sandbox contract v1

Seatbelt profile 使用 `allow default` 后显式：

* `deny network*`；
* `deny file-write*`；
* 只对 canonical project `.lake/build` 与 `.leanbun/tmp` 恢复写权限；
* 只对标准 `/dev` 端点恢复 CLI 写权限。

项目、`.lake`、`.leanbun`、build/temp root 与 protected roots 全部先 realpath，并拒绝 symlink、越界或
protected/write-root 重叠。子进程使用固定 `/usr/bin/sandbox-exec`、参数数组、独立 cwd/environment、30 秒
timeout 和 pipe；不经过 shell。

`.leanbun/binding.json`、项目源码、manifest/toolchain、state root、attestation、provider、registry 与
override 都不在写入 allowlist。未来实际 runner 仍必须由同一进程在 build-time re-verification 成功后直接
调用，不能把 profile 当作可转交的持久 permit。

`98f9b5d5af945f2915f3de1a6a5a3abe4b4a5341bbfbf0f1ccc6599545a78f13`。没有遗留 `.probe-*` 文件。

macOS Seatbelt 不允许在已经应用外层 profile 的进程中再次 `sandbox_apply`，会返回 exit `71` / operation
not permitted。因此常规 `./scripts/dev check` 验证 profile 生成、路径约束与观察判定；真实 Seatbelt
执行使用无外层 sandbox、但最小环境且由内层 profile 自行禁网/限写的专用验收命令。
