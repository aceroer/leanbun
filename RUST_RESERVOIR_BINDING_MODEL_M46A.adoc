== Completion status

M46 Phase A is complete as `0.16.0-m46a-dev`. The authority and compatibility choice was recorded before implementation in
xref:RESERVOIR_BINDING_AUTHORITY_DECISION_M46A.adoc[LeanBun Reservoir Binding Authority Decision M46 Phase A].

The delivered scope is an immutable pure model and strict canonical codec. It contains no registry client, filesystem writer, resolver transition, generation activation or external-project mutation.

== Selected compatibility route

LeanBun retains the strict canonical bytes and reader of `LeanBunLockV1`. A separate `ReservoirBindingDocumentV1` companion disambiguates packages whose user request originated from Reservoir but whose V1 exact source is represented as Git.

The companion belongs to `leanbun-lock`, which still depends only on `leanbun-core`. It uses a separately domain-separated canonical line codec and does not depend on JSON, evidence or lifecycle policy crates.

== Authority model

`ReservoirBindingV1` includes and identity-binds:

* `ReservoirRegistryIdentityV1`;
* `PackageKeyV1`;
* a required requested version;
* observed metadata SHA-256;
* canonical resolved URL;
* exact 40-hex Git commit;
* download integrity;
* verified source-tree SHA-256;
* selected-source identity.

`ReservoirBindingDocumentV1::new` requires a non-empty bounded set, canonicalizes package order, rejects duplicates and verifies every binding against the accompanied lock. URL, exact commit, download integrity, source tree and selected-source identity must equal the locked package facts. The document identity binds both the exact V1 lock identity and every binding identity.

`from_canonical_text` additionally rejects wrong lock identity, noncanonical order or representation, binding/document digest drift and trailing content.

The new public surface is recorded in `architecture/m46a/public-api-additions.tsv`.

== First observation policy fixed for Phase B

The model supports a two-stage rule rather than unconditional “first lookup wins”:

. first online resolution produces durable pending evidence;
. exact download and source-tree verification plus registered build/test occurs before activation;
. activation freezes the reviewed companion identity for offline reproduction;
. later online resolution verifies upstream consistency but reports metadata drift or version rebound instead of overwriting the active binding;
. only an explicit rebind authorization may replace the frozen mapping.

Phase A does not implement those state transitions. It provides the immutable identity material they must consume.

== Remaining boundary

M46 Phase B must implement pending first-resolution evidence, typed audit outcomes, explicit rebind authorization and generation-side companion identity binding. Until that gate closes, the new types carry no activation authority and arbitrary public Reservoir discovery remains closed.
