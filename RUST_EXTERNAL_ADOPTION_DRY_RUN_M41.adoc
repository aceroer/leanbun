== Result

M41 Phase A 已把外部采用流程的第一步收口为 `adopt-dry-run`。当前只授权本库
`test/fixtures/lake-managed-dependency` 充当小型外部候选的模拟器；没有读取或修改外部项目，也没有创建 managed
adoption record、generation、Store object 或项目 `.lake`。

命令使用独立确认 token：

----
leanbun adopt-dry-run REPO PROJECT TARGET --explicit-dry-run
----

`--explicit-managed-project` 不能替代 dry-run token。Phase A CLI 还要求候选 canonical path 精确等于登记 fixture；
其他本库 fixture 和所有外部路径均 fail closed。

== Read-only evidence

Dry-run 在候选库上执行两次稳定 project-input tree snapshot，并在二者之间读取：

* `lakefile.toml` 或 `lakefile.lean` 的稳定 SHA-256；
* `lean-toolchain` 的内容和 SHA-256；
* strict typed `lake-manifest.json` 及 SHA-256；
* path package 的 canonical containment；
* exact Lean/Lake 4.32 root-declaration probe。

Lake probe 只在 `.leanbun-dev/tmp` 的随机 staging 目录编译和运行，源项目保持只读；成功或失败均删除 staging。
前后 tree snapshot 必须完全相等，且项目中不得出现 `.lake`。Tree snapshot 排除 `.git`、`.lake` 和平台生成项，
因此摘要表达源码/config/toolchain/manifest 输入，而不是既有构件。

== Lake manifest correction

该验收发现旧 evidence decoder 对 Lake 1.2 path package 过严。Lake 会规范输出空 `scope` 和
`manifestFile: null`；decoder 现在接受这两个精确值，但继续拒绝非空 path scope、Git-only 字段和错误类型。
登记 fixture 已加入 stable typed manifest 回归。
