== 定位

`leanbun/` 是 Bun-managed / Lake-executed / Lean-compiled 的 package lifecycle manager。Bun 接管 resolved lock、来源获取、完整性、不可变缓存、
事务、锁、并发、恢复、发布与差分；Lake 保留配置/target/build semantics，Lean 保留编译与 kernel。当前权威设计见
xref:BUN_LEAN_PACKAGE_TAKEOVER_M30.adoc[LeanBun Bun-Managed Lean Package Takeover M30]。

它在 Lake 外部管理两个用户权限：

* 更新许可：任何工具链、依赖锁、依赖源码和依赖镜像变更必须经过显式事务；
* 编译许可：项目源码可以正常编译，锁定依赖不得在普通构建中被静默源码重编译。

LeanBun 的直接目标是消除同一台机器上不同项目反复构建同一份 mathlib 的现象，并使每一次
依赖更新、缓存恢复、源码回退和本地编译都有可审计依据。

== 当前边界

当前仍保持以下边界：

* 只有 `.leanbun-dev` 内已绑定 fixture 可进入受控 Lake 探针；
* 不迁移或删除现有 mathlib 缓存；
* 不把现有依赖目录改为只读；
* 不修改任何活动项目的依赖绑定；
* 不按时间自动恢复遗留 `running` 记录；同一 project/image 并发构建会被排他锁拒绝；
* Rust 已能只读验证 lock，但不会获取、释放、删除或恢复 lock；
* `leanbun-state` 纯函数实验不接入 CLI、不继续实现 writer，也不解释或改变 Lake 内部状态；
* Rust 外部包 inventory 已建立，但 checkout 未观察不会被报告为 matched，也不会触发修复；
* Rust Lake update plan 只生成不执行，bare update 与 path/unknown package 均拒绝；
* 固定 Lake update 契约已锁定 source hash 与行级事实，但只验证 plan，未开放 process adapter；
* canonical plan report 已可供人工审阅，但不是许可记录，也不是执行队列；
* approval request 仍为 `pending`/`withheld`；虽已绑定完整 inventory snapshot，但尚未通过 fresh preflight；
* preflight 只能给出 `ReadyForExplicitApproval`，不能给出执行许可；
* 外部 grant JSON 仍只能成为 structural claim；M19 已把可信 launch intent durable reserved once，M20 已确认当前 macOS/Rust/Bun
  没有可接受的 safe FD-bound executable handoff；M21 又将当前 user-owned/noowners-volume 生产 Lake 分类为 mutable-path denied，因而仍
  没有 process adapter 或 CLI dispatch；M22 已由新 observer 实测为 `DeniedUserOwnedComponent`；fresh
  checkout 一律保守标为 `Unobserved`，不会运行 Git 发现；M23 完成 ACL/native API 审计并确定独立 FFI crate 边界；
* M24 已建立独立只读 ACL wrapper 并确认生产 volume `MNT_IGNORE_OWNERSHIP`；当前路径仍是
  `DeniedUserOwnedComponent`，没有 process adapter 或 CLI dispatch；
* M25 已建立 non-consuming reservation-bound assessment；fresh rehash/path observation 的所有结果仍为 typed denial +
  `Withheld`，reservation slot 不会被读取、修改或删除；
* M26 确认 sealed system binary 不能作为自定义 Lake acquisition route；root-owned install 与 privileged read-only image 仍需外部 privileged
  coordinator，user-mounted image 与 user-owned toolchain 继续拒绝；
* M27 确认 `SMAppService` daemon 与 signed-peer XPC 只是 host/transport candidates；现有 M19 capability 不可直接 IPC 化，M25 在 root daemon
  中使用了错误的 implicit effective UID，因此 coordinator protocol 尚未建立；
* M28 已建立 principal-explicit pending request identity；M29 已建立固定 21-field canonical envelope 与 strict decoder，并通过 Rust/Bun wire
  golden；该 privileged/XPC 路线现为可选安全研究，不再阻塞 Bun package takeover 主线；
* M30 已冻结 Bun-managed / Lake-executed / Lean-compiled 权威边界；`leanbun.lock` 是 resolved graph 权威；Bun 对 manifest、workspace override、
  runtime override 三类 provenance 显式排序、拒绝重复/冲突并为每包确定唯一 final path，Lake 只接收 Bun-only runtime projection；
* M31 lock/final-path model 与 M32 Lake bridge 已完成；隔离 fixture 可只读归一 TOML/Lean declarations、生成完整 manifest/runtime projections、由 exact Lake 解析并比较
  Mathlib 九包实际路径；
* M33 pure resolver 已完成：只消费 supplied metadata，按 Lake reverse breadth-first/root-priority/later-shadow 规则生成 exact graph，并对 frozen/update pin、shadow/conflict、
  cycle/depth/toolchain/source drift fail closed；
* M34 immutable store 已完成：只对 `.leanbun-dev-rust/store-fixture` 开放受限 writer，本地 mock fetch、完整性、安全解包、并发 dedupe、故障清理、只读对象发布与离线重验已通过；该门自身不发布 active generation；
* M35 active generation 已完成：只对 `.leanbun-dev-rust/generation-fixture` 开放 writer，以 active record 为唯一 commit point，所有 commit 前后 crash 均按确切记录恢复，旧 generation 与 store 引用只保留不自动删除；
* M36 supervised offline build 已完成：固定 Lake/profile SHA、参数/环境/target/deadline/output，Seatbelt 禁网，实际 `LEAN_PATH` 与 Bun 路径集合精确比较，dependency-free/Mathlib fixture 离线构建，build-image 排他/复用/漂移/崩溃恢复通过；
* M37 repository-local acceptance 已完成：`lake-basic` 的固定隔离副本通过 precommit 故障恢复、实际路径观察、Lake nonzero、两轮构建、build-image publish/reuse 和 retained-generation 原子 rollback；

* M40 已完成：local path 与 registered Git dependency graph 均进入同一 controller；Mathlib 九包真实传递边、并发 store、Bun final paths、cache seed、离线 build、recovery 与 rollback 已由本库 fixture 验证；外部项目仍未采用；

  execution copy，并由 mutable `latest.record` 指向最近一次已完成记录；

* M42 Phase C 已完成：`mathlib-project` 九包完整闭包可重复执行同一事务链；两次运行均保持登记模板不变、
  恢复后无 active temp，并清理项目副本、controller state 与 project-local store；

== Rust 源码构建与历史验证

clean clone 的默认 Rust 源码检查不读取生产 provider、Keychain、Developer ID 或 notarization 配置：

[source,shell]
----
cd rust
cargo test
cargo clippy --all-targets -- -D warnings
----

仓库隔离 wrapper 的主线与历史入口分别为：

[source,shell]
----
./scripts/rust-dev check
./scripts/dev historical-check
----

`./scripts/dev check` 额外运行本机登记的 Bun/Lean integration，因此需要先从
`config/leanbun-local-provider.example.json` 建立 Git 忽略的
`config/leanbun-local-provider.json`。该机器配置不是源码构建依赖，也不会进入公开仓库。
